# Тестовое задание: Архитектура системы бронирования и аналитики в реальном времени (микро-SaaS)
## Контекст задачи
Вам необходимо разработать прототип сервиса для аренды рабочих мест (Coworking Booking Platform). Система должна обрабатывать высокую нагрузку в пиковые часы (например, в 9:00 утра, когда все одновременно бронируют места) и предоставлять администраторам аналитику занятости в реальном времени.

## Технологический стек
Backend: Node.js (TypeScript).

Frontend: React (TypeScript), стейт-менеджер Zustand.

Базы данных и кеш: PostgreSQL + Redis.

Архитектурный подход: Разделение на слои, DDD (Domain-Driven Design) на фронтенде.

## Технические требования
1. Backend (Node.js / TypeScript)
Предотвращение Overbooking (Двойного бронирования): Реализовать надежный механизм, исключающий ситуацию, когда одно рабочее место бронируется двумя пользователями на одно и то же время при конкурентных запросах. Использовать оптимистические/пессимистические блокировки в БД или распределенные блокировки (Distributed Locks) через Redis.

API Layer: REST API. Обязательна валидация входящих данных и строгая типизация.

Real-time Analytics: Реализовать WebSocket-сервер, который транслирует администраторам текущую заполняемость коворкинга при каждом успешном бронировании.

Оптимизация производительности: Написать сложную логику выборки свободных мест за диапазон дат с использованием индексов или кеширования в Redis.

2. Frontend (React / TypeScript)
Архитектура: Четкая структура проекта по методологии FSD. Минимизация сквозных зависимостей.

Интерфейс бронирования: И интерактивная карта мест, которая обновляется в реальном времени, если место занял кто-то другой.

Оптимизация рендеринга: Исключить лишние ререндеры при обновлении данных по WebSockets. Разумное использование useMemo, useCallback, React.memo и кастомных хуков. Strict typing — никаких any.

Обработка состояний (State Management): Чистая работа с асинхронными запросами, обработка ошибок, состояний загрузки (Race Conditions, Skeletons).

3. DevOps & Инфраструктура
Docker: Окружение должно подниматься одной командой docker-compose up --build (Node.js app, React app, PostgreSQL, Redis).

Миграции и сиды: База данных должна автоматически инициализироваться и наполняться тестовыми данными при старте.

Все задачи будут описаны в отдельных папках в директории .agent/tasks/. Внимательно читай описание задачи. К следующей задаче приступай только после того, как текущая будет полностью завершена. Если задача понятна, дай ответ "Задача понятна" и жди команды к старту реализации. Если возникнут вопросы - задавай их, а не начинай делать без уточнений.
