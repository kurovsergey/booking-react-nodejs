# Отчет по задаче: 01-Docker-Init (Инициализация Docker-окружения)

## Описание проделанной работы

В рамках задачи была разработана и внедрена базовая конфигурация контейнеризации для проекта **Coworking Booking Platform (Микро-SaaS)**. Это обеспечивает быстрый, стабильный и воспроизводимый запуск всех компонентов системы одной командой.

Были выполнены следующие работы:
1. **Dockerfile для Backend (`./backend/Dockerfile`)**:
   - Использован легковесный базовый образ `node:20-alpine`.
   - Настроена рабочая директория `/app`.
   - Обеспечена корректная установка зависимостей через `npm install`.
   - Настроен запуск в режиме разработки (`npm run dev`) и проброс порта `5000`.

2. **Dockerfile для Frontend (`./frontend/Dockerfile`)**:
   - Использован аналогичный базовый образ `node:20-alpine`.
   - Настроена рабочая директория и копирование пакетов.
   - Обеспечен запуск dev-сервера (Vite) на порту `5173`.

3. **Оркестрация сред (`./docker-compose.yml`)**:
   - Описаны 4 ключевых сервиса: `db` (PostgreSQL 16), `redis` (кэш/брокер), `backend` и `frontend`.
   - Для всех сервисов настроена политика автоматического перезапуска `restart: always`.
   - Создана выделенная мостовая сеть `coworking-net` для безопасного изолированного взаимодействия контейнеров.
   - Настроен маппинг портов для внешнего доступа к БД (`5432`), Redis (`6379`), бэкенду (`5000`) и фронтенду (`5173`).
   - Настроена постоянность данных (volumes) для `pgdata` и `redisdata`.
   - Внедрены механизмы отслеживания готовности сервисов (`healthcheck`), благодаря которым `backend` запускается строго после того, как PostgreSQL и Redis станут полностью готовы принимать соединения.
   - Настроен маппинг исходного кода хост-системы внутрь контейнеров для удобной live-разработки (с исключением `node_modules` через анонимные тома).

4. **Документирование (`README.md`)**:
   - Добавлены понятные инструкции для разработчиков по быстрому старту (`docker-compose up --build`), остановке и полной очистке volumes.

## Используемые технологии

* **Docker & Docker Compose** (версия схемы 3.8)
* **Node.js v20 (Alpine Linux)** — среда выполнения для бэкенда и фронтенда
* **PostgreSQL 16 (Alpine)** — реляционная СУБД
* **Redis (Alpine)** — нереляционная СУБД для кэширования и распределенных блокировок

## Возникшие проблемы и пути их решения

| Проблема | Причина | Решение |
| :--- | :--- | :--- |
| **Падение Backend при старте** | Бэкенд пытался подключиться к PostgreSQL сразу при старте контейнера, но СУБД требовалось несколько секунд для инициализации структуры и готовности принимать TCP-соединения. | Настроен полноценный `healthcheck` для СУБД с вызовом `pg_isready` и для Redis с `redis-cli ping`. В бэкенд добавлен блок `depends_on` с условием `condition: service_healthy`. |
| **Различие в node_modules** | При локальном запуске на Windows и монтировании папки в Linux-контейнер могли возникать ошибки компиляции из-за бинарных зависимостей `node_modules`. | В секцию `volumes` для frontend и backend добавлен анонимный том `/app/node_modules`, который маскирует локальную папку хоста и использует зависимости, установленные непосредственно внутри Linux-контейнера. |
